# Rayye Smart Irrigation

Rayye is a Flutter application for monitoring plant zones and managing a smart
irrigation system. The app provides authentication, zone configuration,
moisture monitoring, automatic watering rules, manual pump controls, alerts,
and a device-connection setup flow.

The current release is an MVP. The irrigation controller is simulated in the
app, so the Wi-Fi, MAC address, Arduino, ESP32, and Raspberry Pi selections do
not yet communicate with physical hardware.

## Features

### Authentication

- Firebase email/password sign-in
- New-user registration
- Password reset email flow
- Logout with confirmation
- Authentication state restoration when the app starts

### Irrigation Dashboard

- Average zone moisture
- Active pump count
- Water usage and tank status indicators
- Online/offline system status
- Automatic irrigation toggle
- Zone cards with current moisture and status

### Zone Management

- Add a zone with plant, soil, and sensor information
- Configure each zone's moisture threshold
- View zone moisture history and last-watered time
- Manually start or stop a zone pump
- Remove zones

### Device Connection

The Settings screen opens a connection form with these choices:

- Connection method: Wi-Fi, MAC address, or Wi-Fi + MAC address
- Device type: Arduino, ESP32, or Raspberry Pi
- Wi-Fi address or hostname
- MAC address

The form validates the fields required by the selected connection method. A
successful submission currently creates simulated zones and returns to the app.

### Alerts and Activity

The Alerts tab displays events generated by the irrigation simulation, including
watering activity, low-moisture warnings, pump changes, and automatic-mode
changes.

## Requirements

- Flutter SDK with Dart support for the SDK constraint in `pubspec.yaml`
- Android Studio and an Android SDK for Android development, or Xcode for iOS
- A configured Firebase project for authentication
- A device or emulator supported by Flutter

Verify the local Flutter installation with:

```bash
flutter doctor
```

## Setup

1. Clone the repository and open the project directory.
2. Install Dart and Flutter dependencies:

	```bash
	flutter pub get
	```

3. Configure Firebase for the platforms you intend to run. The repository
	includes `lib/firebase_options.dart`, `firebase.json`, and an Android
	`google-services.json`, but each developer or deployment environment should
	verify that the Firebase project and platform identifiers are correct.
4. Run the application:

	```bash
	flutter run
	```

The application starts with Firebase authentication initialization. New users
can register, sign in, and then access the Dashboard, Alerts, and Settings tabs.

## Application Architecture

`main.dart` creates the app-level `IrrigationService` with Provider and creates
an `AuthBloc` backed by `FirebaseAuthProvider`. `HomePage` listens to the auth
state and selects the appropriate entry view:

```text
FirebaseAuthProvider
		  │
		  ▼
	 AuthBloc ──► HomePage ──► Login/Register/Forgot Password
											 │
											 ▼
										 AppShell
								 ┌────────┼────────┐
								 ▼        ▼        ▼
						  Dashboard  Alerts  Settings
```

`IrrigationService` owns the current zones, auto-irrigation setting, system
status, and notifications. It extends `ChangeNotifier`, and the dashboard,
alerts, settings, and zone screens read the shared state through Provider.

## Simulation Behavior

Until hardware integration is implemented, `IrrigationService` runs a timer
every four seconds:

- Pumping zones gain a small random amount of moisture.
- Inactive zones gradually lose moisture.
- Auto mode starts a pump when moisture drops below its threshold.
- A pump stops after the moisture reaches the threshold plus 20 percentage
  points.
- Notifications are added for watering, low moisture, pump changes, and mode
  changes.

All irrigation state is held in memory and is lost when the application is
restarted. The device connection form currently uses its values for validation
and selection only; it does not perform network, Bluetooth, serial, HTTP, or
platform-channel communication.

## Localization

Localization is configured in `l10n.yaml` with `lib/l10n/app_en.arb` as the
template. Generated localization files are placed in `lib/l10n`. Most current
dashboard and irrigation labels are still written directly in the widgets, so
future localization work should move those strings into ARB resources.

## Testing Notes

The current test suite covers:

- Authentication provider behavior using an in-memory test implementation
- A smoke test verifying that `HomePage` loads without an exception

Hardware communication, Firebase integration, persistence, irrigation timing,
and full screen interaction flows do not yet have automated integration tests.
